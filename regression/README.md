# Elasticsearch ML Regression — IT Incident Resolution Time

A minimal example of Elasticsearch's [Data Frame Analytics](https://www.elastic.co/guide/en/elasticsearch/reference/current/ml-df-analytics-overview.html) regression, using a synthetic IT incident dataset.

## What it does

1. **Generates** 600 synthetic IT incident records and bulk-indexes them into `it-incidents`.
2. **Creates and starts** a data frame analytics regression job that trains on 80 % of the data, predicting `resolution_time_minutes` from seven operational features.
3. **Writes results** to `it-incidents-regression-results`, where each document gets a `ml.resolution_time_minutes_prediction` field and per-feature importance scores.

## Prerequisites

- Python 3.8+
- An Elastic Cloud Serverless project **or** a self-managed Elasticsearch 7.8+ cluster with a Platinum/Enterprise licence
- No third-party Python packages required — only the standard library

## Setup

### 1. Credentials

Create `.env` in the **repo root** (`ml-jobs/`). The scripts walk up from their own location, so a single file at the root covers all jobs.

```bash
# ml-jobs/.env
ELASTICSEARCH_URL=https://<your-endpoint>.es.<region>.gcp.elastic.cloud
ELASTICSEARCH_API_KEY=<your-api-key>
```

### 2. Required API key privileges

| Privilege | Scope |
|---|---|
| `manage_ml` | cluster |
| `create_index`, `index`, `read` | `it-incidents`, `it-incidents-regression-results` |

## Usage

### Step 1 — Index sample data

```bash
python3 generate_sample_data.py
```

Expected output:
```
Total records to index: 600
  Indexed 300/600
  Indexed 600/600
Done.
```

### Step 2 — Create and start the ML job

```bash
python3 setup_regression_job.py
```

Expected output:
```
Documents in it-incidents: 600

Creating job 'incident-resolution-regression'...
  id: incident-resolution-regression
  dest index: it-incidents-regression-results

Starting job 'incident-resolution-regression'...
  acknowledged: True
```

### Step 3 — Poll job status

```bash
curl -s -H "Authorization: ApiKey $ELASTICSEARCH_API_KEY" \
  "$ELASTICSEARCH_URL/_ml/data_frame/analytics/incident-resolution-regression/_stats" \
  | python3 -m json.tool | grep -E "state|progress_percent"
```

State transitions: `stopped` → `started` → `reindexing` → `analyzing` → `writing_results` → `stopped` (100 %)

### Step 4 — Query results

Top 10 longest predicted resolution times (test set):

```bash
curl -s -H "Authorization: ApiKey $ELASTICSEARCH_API_KEY" \
  -H "Content-Type: application/json" \
  -X POST "$ELASTICSEARCH_URL/it-incidents-regression-results/_search" \
  -d '{
    "size": 10,
    "query": {"term": {"ml.is_training": false}},
    "sort": [{"ml.resolution_time_minutes_prediction": {"order": "desc"}}],
    "_source": ["incident_id", "category", "severity", "num_affected_users",
                "team_size", "is_business_hours", "resolution_time_minutes",
                "ml.resolution_time_minutes_prediction"]
  }' | python3 -m json.tool
```

Average predicted vs actual resolution time by category:

```bash
curl -s -H "Authorization: ApiKey $ELASTICSEARCH_API_KEY" \
  -H "Content-Type: application/json" \
  -X POST "$ELASTICSEARCH_URL/it-incidents-regression-results/_search" \
  -d '{
    "size": 0,
    "query": {"term": {"ml.is_training": false}},
    "aggs": {
      "by_category": {
        "terms": {"field": "category", "size": 10},
        "aggs": {
          "avg_actual":    {"avg": {"field": "resolution_time_minutes"}},
          "avg_predicted": {"avg": {"field": "ml.resolution_time_minutes_prediction"}}
        }
      }
    }
  }' | python3 -m json.tool
```

Average predicted resolution time by severity:

```bash
curl -s -H "Authorization: ApiKey $ELASTICSEARCH_API_KEY" \
  -H "Content-Type: application/json" \
  -X POST "$ELASTICSEARCH_URL/it-incidents-regression-results/_search" \
  -d '{
    "size": 0,
    "aggs": {
      "by_severity": {
        "terms": {"field": "severity", "size": 5, "order": {"_key": "asc"}},
        "aggs": {
          "avg_predicted": {"avg": {"field": "ml.resolution_time_minutes_prediction"}}
        }
      }
    }
  }' | python3 -m json.tool
```

## Sample dataset

| Field | Range / Values | Type |
|---|---|---|
| `severity` | 1 (low) – 5 (critical) | integer |
| `category` | network, hardware, software, security, user_access | keyword |
| `num_affected_users` | 1–300 | integer |
| `team_size` | 1–8 | integer |
| `hour_of_day` | 0–23 | integer |
| `day_of_week` | 0 (Mon) – 6 (Sun) | integer |
| `is_business_hours` | 0 or 1 | integer |
| `num_comments` | 2–60 | integer |
| `resolution_time_minutes` *(target)* | ~5–1000 | float |

Resolution time is generated by a deterministic formula (category base + severity + affected users + comment overhead, discounted by team size, penalised off-hours) with ±8 % Gaussian noise, giving the model a real signal to learn.

## ML job configuration

| Parameter | Value |
|---|---|
| Source index | `it-incidents` |
| Dest index | `it-incidents-regression-results` |
| `dependent_variable` | `resolution_time_minutes` |
| `training_percent` | `80` |
| `num_top_feature_importance_values` | `7` |
| `model_memory_limit` | `100mb` |

`num_top_feature_importance_values: 7` adds `ml.feature_importance` to each result document, showing which features (e.g. `severity`, `is_business_hours`) pushed the predicted resolution time up or down for each individual incident.

## Cleanup

```bash
# Delete the ML job
curl -s -X DELETE -H "Authorization: ApiKey $ELASTICSEARCH_API_KEY" \
  "$ELASTICSEARCH_URL/_ml/data_frame/analytics/incident-resolution-regression"

# Delete both indices
curl -s -X DELETE -H "Authorization: ApiKey $ELASTICSEARCH_API_KEY" \
  "$ELASTICSEARCH_URL/it-incidents,it-incidents-regression-results"
```
